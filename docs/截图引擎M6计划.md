# 自研截图引擎 M6 计划

> 2026-10-11 立项。系统截图（GNOME 内建 UI）闭源不可扩展，缺长截图/活动
> 窗口截图/钉住（贴图）等常用功能 → 自研完整截图引擎。本文档固化调研结论、
> 可行性实证与分批落地；关联：[插件基座M5计划.md](插件基座M5计划.md)。

## 0. 可行性实证（本机 GNOME 50.1 Wayland，2026-10-11 实测）

| 通道 | 结果 | 结论 |
|---|---|---|
| `org.gnome.Shell.Screenshot` D-Bus | ❌ **Access denied** | Flameshot 式「Shell 抓全屏 + 自绘覆盖层」不可行 |
| `org.gnome.Shell.Introspect GetWindows` | ❌ **Access denied** | 窗口枚举被收紧，活动窗口几何需另找来源（ATSPI） |
| portal Screenshot 非交互 | ✅ 首用弹授权框，「允许」后静默 | **唯一合规像素来源**（yihu-panel 自 M4 起已持有授权） |
| portal ScreenCast（PipeWire） | ✅ 通道存在 | 实时帧来源（后续长截图/录屏方向，需一次授权） |
| GTK4 定位/keep-above | ❌ Wayland 不允许 | 窗口移动走 begin_move（合成器接管）；贴图窗普通层级 |

## 1. 同类产品功能全景（调研 2026-10-11）

Snipaste（元素检测/贴图/马赛克/取色）、PixPin（长截图/OCR/GIF/翻译）、
Flameshot（放大镜/标注全家桶/pin）、ShareX（滚动截图/OCR/任务链）、
CleanShot X/Shottr（滚动/标注/像素尺/二维码）、GNOME 内建（无标注）、
uTools/ZTools 插件（截图标注/长截图/screen-to-gif）。共性核心 =
「呼出 → 区域捕获 → 标注 → 复制/保存/贴图」；差异化在长截图/OCR/贴图/GIF。

## 2. 分批

### 第一批（本批，已落地）：引擎底座 + 区域截图 + 贴图

- `panel/shotengine.rs`：portal 冻结帧（PNG 字节跨线程，主线程解码）+
  选区→像素换算（`crop_pixels`，与帧求交）+ 保存（XDG Pictures/Screenshots）。
- `panel/overlay.rs`：自绘选区覆盖层——每显示器一个全屏窗（fullscreen_on_monitor
  钉屏），冻结帧铺底 + 四块遮罩 + 选区边框/尺寸提示；拖框、**Esc 取消 ·
  Enter/双击 复制 · P 贴图 · S 保存**；v1 选区限单屏内、统一缩放因子。
- `panel/pin.rs`：贴图窗（GtkPicture）——按下拖动 = begin_move 原生移动
  （gdk4 绑定缺 Surface→Toplevel IsA，按 C 语义直转接口指针）、滚轮缩放、
  双击复制并关、Esc 关；钉剪贴板图 = gdk 异步读纹理。层级限制：GTK4/
  Wayland 无 keep-above，贴图窗普通层级。
- 接线：全局热键 Ctrl+Alt+A 改走自研引擎；面板宫格「区域截图」「贴图」
  磁贴；搜索行（jietu/quyu、tetu/pin 命中）；sys:screenshot 保留为
  「系统截图工具」兜底。全程审计（shot.region/shot.pin）。

### 第二批（待排期）：长截图

- 前置：本批引擎（冻结帧 + 区域选区）。
- 架构：选区确认后进入「滚动捕获」模式——循环调 portal 全屏截图（授权后
  静默，约 2-5 fps）+ 用户手动滚动 → 纵向拼接（相邻帧按行差异求重叠偏移，
  纯 Rust 可实现，无 OpenCV）；Esc 结束拼接出长图。
- 风险：portal 调用延迟（~300-500ms/帧）限制捕获流畅度；PipeWire
  ScreenCast（实时帧）是终态方向，作为二期升级路径。

### 第三批（待排期）：活动窗口截图 + 标注编辑器

- 活动窗口：Shell Introspect 已被拒 → 几何来源评估 ATSPI（zbus 已是面板
  依赖，可手写 AT-SPI2 窗口枚举/GetExtents）或启发式边缘检测；未定。
- 标注编辑器：覆盖层确认后进编辑器窗（GTK cairo 画布）：矩形/椭圆/箭头/
  文字/马赛克/像素化/序号步进 + 撤销重做（对标 Flameshot）。

### 明确不做 / 远期

- 元素级自动吸附（Snipaste 独家，依赖 Windows UIAutomation，Linux 无对等）。
- 图片 AI 翻译（依赖大模型 API，适合做成插件经 network.fetch）。
- GIF 录制（GNOME 内建录屏可先用；远期可接 portal ScreenCast）。
