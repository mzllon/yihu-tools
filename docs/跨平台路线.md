# 跨平台路线（Windows 10 / deepin / Fedora）

> 2026-10-11 立项。目标变更：一呼的目标平台从「Ubuntu/GNOME Wayland」扩展为
> **Windows 10 + deepin/Fedora 等 Linux 桌面**。本文档回答：哪些能带走、哪些
> 必须重构、分几步走。关联：[插件基座安全模型与发布策略.md](插件基座安全模型与发布策略.md)。

## 0. 结论
## 0. 结论

> **2026-10-11 用户拍板追加**：①官方插件采用 **Rust 原生实现**（SDK 化，
> 编译为各自独立二进制），第三方插件采用 **WASM**；②基座重构为跨平台
> 架构，**性能第一顺位**。对本文的影响：Stage 2 的插件沙箱项升级为
> 「Rust 原生二进制（Linux/Windows 同源码交叉编译）+ WASM（第三方）」
> 双轨；Python 官方插件分批迁移至 yihu-plugin-sdk（首批 7 个零/低能力
> 插件已落地，能力重的 radio/hotkeys/screenshot/mdkit 随后）。

1. **值得重构，但不是推倒**。能力@参数改造 + mdrender/datactl 下沉已经把
   80% 的可移植性做完了：协议、插件注册表、16 个纯计算插件、Markdown
   渲染管线、数据管理全部平台无关。绑住手脚的是**宿主层的平台实现**，
   重构 = 把它们收拢成显式的平台后端接口，不是换 UI 栈重写。
2. **插件基座不需要重构，需要的是"沙箱后端"抽象**：bwrap（Linux namespace）
   在 Windows 不存在。Windows 10 上官方插件以普通进程运行（信任模型收缩
   为官方签名插件），第三方插件的终态回到安全文档预埋的 WASM/WASI。
3. **顺序**：先 Linux 跨发行版（Fedora 成本≈0，deepin 有两个硬点），
   再 Windows spike 定工作量，最后全量迁移。Ubuntu 主干在全程保持可用。

## 1. 平台耦合盘点（现状实测）

### 完全平台无关（直接带走）

| 层 | 内容 |
|---|---|
| 协议 | stdio 行式 JSON v1、init/query/results/activate、ui.show 模板 |
| 能力模型 | 能力@参数声明制、授权/审计框架（后端实现各异，接口不变） |
| 16 个纯计算插件 | devcodec/sqlfmt/cronkit/csvkit/mdkit/todo/randgen/passgen/
ts-convert/jsonkit/qrtool…全部 Python 标准库，零平台依赖 |
| 渲染 | pulldown-cmark + ammonia（yihu-core::mdrender）、TOAST UI 编辑层 |
| 数据 | 插件注册表布局、datactl 数据管理、审计 JSONL |

### Linux 通用、非"开箱即有"

bwrap（flatpak 发行版自带，其余要装）、portal（跨桌面标准，后端行为各异）、
GStreamer/pactl/notify-send/xdg 路径、zbar-tools/pandoc/qrencode（各发行版
都有包，安装提示要按发行版探测）。

### GNOME 专属（重构主战场）

| 模块 | 绑定点 | Windows 对应 |
|---|---|---|
| 面板定位 placer 扩展 | GNOME Shell/Mutter | SetWindowPos（反而更容易） |
| 全局热键（gsettings media-keys） | GNOME | RegisterHotKey |
| autodark（gsettings color-scheme + systemd timer） | GNOME/systemd | 注册表 + 计划任务/进程内定时 |
| 托盘 ksni | freedesktop（GNOME 需扩展） | 原生托盘 |
| 通知 notify-send | freedesktop | WinRT toast |
| 音量 pactl | PipeWire/PulseAudio | WASAPI |
| 电台播放 gst-play | GStreamer（Windows 有但重） | mpv/WASAPI |
| 截图 portal | freedesktop（Linux） | DXGI/GDU/GDI 捕获——冻结帧+覆盖层架构可移植 |
| **状态/资源** /proc | Linux | Toolhelp32/WMI |
| **沙箱** bwrap | Linux namespace | v1 无沙箱（官方插件直跑）；终态 WASM |
| **D-Bus** 服务（panel↔center） | 会话总线 | 命名管道/本地 TCP |
| **mdworkbench 的 WebKitGTK** | Linux 专属（Windows 无 WebKitGTK 移植） | **wry/WebView2**——TOAST UI 编辑层原样带走，这是选 web 技术栈的回报 |

### 依赖 Windows 的Linux 侧注意项

- GTK4 在 Windows 可编译可运行（很多应用在用），观感打折但成立——panel/
  center 不换 UI 栈是当前的可行路径；
- Python 插件：Windows 随包带 **Python embeddable 发行版**（~10MB）；
- 深色模式/开机自启：注册表。

## 2. 分阶段

### Stage 1：Linux 跨发行版（Fedora 即刻，deepin 部分）——成本低

1. **包提示发行版自适应**：/etc/os-release 探测 → apt/dnf/pacman/zypper
   （radio gst 依赖、zbar-tools、pandoc 三处提示）；
2. **平台后端抽取**：把 panel 内的 gsettings/热键/通知/音频/截图/路径
   收拢为 `PlatformShell` trait（Ubuntu 实现即现有代码，行为零变化）；
3. **诚实边界**：KDE/deepin 的 Wayland 全局热键与面板定位无对等机制，
   v1 声明「GNOME 桌面优先，KDE 未适配」——三大件（placer/gsettings/
   扩展）重写不做。

### Stage 2：Windows 10 spike（先验证再定全量工作量）

最小验证单（每个半天级）：
1. panel/center 在 Windows 编译运行（GTK4 Windows 包）；
2. mdworkbench 换 wry/WebView2（TOAST UI 层零改动——关键验证）；
3. 截图引擎：DXGI 冻结帧 + 现有覆盖层逻辑；
4. RegisterHotKey + toast 通知；
5. 插件：Python embeddable 随包 + 官方插件直跑（无沙箱）。
spike 结果决定：全量迁移排期、哪些能力 Windows v1 缺席（如 audio.pactl
音量 → WASAPI 重写）。

### Stage 3：全量迁移 + 沙箱终态

- PlatformShell 的 Windows 实现（清单 = Stage 2 结果）；
- 插件沙箱：官方签名插件直跑 → 第三方 WASM/WASI（wasmtime，Windows/
  Linux 同一运行时，安全文档 §3.3 的终态在此兑现）；
- D-Bus → 本地 RPC（named pipe）。

## 3. 不做清单

- KDE/deepin 的面板定位与全局热键对等实现（Wayland 协议层面缺失，成本
  无上限）——deepin 上以「部分功能可用」发布并明示；
- GTK 之外的 UI 栈重写（Qt/Electron）——GTK4 Windows 可用，重写无收益；
- Windows 版市场签名链（等 Linux 侧签名信任根落地后复用设计）。

## 4. 立即可做（不动主干）

- 包提示发行版自适应（小时级）；
- `PlatformShell` trait 抽取（把 panel 的平台调用点收拢，Ubuntu 实现即
  现有代码，重构即净化）；
- 安全文档增补「Windows 信任模型收缩」章节（官方插件直跑的边界与签名单）。
