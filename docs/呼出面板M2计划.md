# 呼出面板 M2 计划（真实提供者）

> 依据：[呼出面板调研](呼出面板调研.md) §4。状态：**已完成（2026-09-16）**。
> 目标：演示数据 → 真实搜索：应用启动、内置能力、算式计算。
> 性能红线不回退：待命 PSS ≤ 30 MB、暖 toggle < 100 ms、show 路径零 IO。

## 交付内容

- **F1 条目真实化**：列表项携带 `kind/payload/icon_spec`（"app" / "cap" / "calc"），
  激活分发真实动作后自动隐藏；行首换 `gtk::Image::set_from_gicon` 真图标
  （ThemedIcon 名 / FileIcon 路径 / 兜底 executable-symbolic）。
- **F2 应用提供者**：启动时 `gio::AppInfo::all()` + `should_show()` 过滤，
  显示名进 nucleo，激活 `DesktopAppInfo::launch()`；运行期新装应用需重启面板（M3 刷新）。
- **F3 能力提供者 v0**（进程内）：切换深色/浅色（`autodark::set_scheme`，后台线程）、
  打开一呼中心、打开广播页/主题切换页（spawn `yihu --page …`）。
- **F4 计算器**：`calc.rs` 递归下降（`+ - * / % ^`、括号、一元正负号、右结合幂，
  无外部 crate）；可解析时置顶「= 结果」行，回车复制（面板持焦时 Wayland 可写剪贴板）。
- **F5 中心 `--page` 深链**：`HANDLES_COMMAND_LINE` + `add_main_option` +
  `connect_command_line`；build 移入命令线路径，UI 句柄存 thread_local
  （GTK 对象非 Send，不能进 static）。
- **F6 历史/默认集**：`panel_history.json`（mt-core `History`），激活后台落盘；
  空输入 = 能力置顶 → 最近使用应用（次数/时间序）→ 其余应用。
- **F7** 空态「无匹配」行；移除 M1 演示数据。

## 实测结果（release，Ubuntu 24.04 / Wayland）

| 指标 | 门槛 | 实测 | 结论 |
|---|---|---|---|
| 待命 RSS / PSS | PSS ≤ 30 MB | **~43 MB / ~14 MB** | ✅ 远优于门槛（M1 为 71/25：移除 1 万条演示数据后工作集大幅缩小） |
| 暖 toggle 全程 | < 100 ms | **~10 ms** | ✅ |
| show 路径 IO | 0 | 0 | ✅ 枚举/历史均在启动时 |
| 应用枚举 | — | ~9 ms（61 可见应用，一次性） | ✅ |
| 打包测试 | 全绿 | PASS | ✅ |

真机回归：中心 `--page radio` 冷启动正常；二次 `--page autodark` 立即转发
（exit=0）并切换页面置前；自启 desktop（无参 Exec）路径不受
HANDLES_COMMAND_LINE 影响（命令线路径兜底建 UI）。

## 过程记录

- 计算器优先级 bug：初版文法把一元负号放在幂之上，`-2^2` 得 4；
  修正为「指数侧才允许一元符号」的文法（`-2^2 = -4`、`2^-3 = 0.125`），
  并补充 `(1+2` 缺右括号拒绝等测试。
- 真机深链一度失败，根因是**旧版中心进程仍持有总线名**（跑在开发目录上，
  不认识命令行转发）——升级后需重启中心。此为运维现象，非代码缺陷。
- gio 0.20 的 `launch()` 签名带 AppLaunchContext 参数；
  `VariantDict::lookup` 无 depth 参数——以实际 API 为准修正。
