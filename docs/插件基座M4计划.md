# 插件基座 M4 计划（第二期）

> 依据：[插件基座调研](插件基座调研.md) §3/§5、[插件基座 M3 计划](插件基座M3计划.md)「遗留到 M4+」。状态：**一期 + 二期主体已落地（2026-10-07）**，剩余项见「实施状态」。
> 安全基线见：[插件基座安全模型与发布策略](插件基座安全模型与发布策略.md)。
> 宗旨：延续「性能高、资源占用率低」。本期主题 = **安全收口 + 生态分发 + UI 形态决策**：
> 权限从「声明 + 明示」走向宿主强制的最小能力与沙箱；插件从「本地目录手工装」走向「可追溯构建物 + zip 一键装 + 市场审核」；
> 并用实测数据敲定 UI 插件的进程形态。

## 0. 实施前必须冻结的安全边界

1. **独立进程不等于安全隔离**：M3 插件是由 `yihu-panel` 按需拉起的独立进程，stdio 和进程组只解决协议与生命周期；当前权限字段仍主要是声明/展示，不能阻止插件自行访问系统。
2. **宿主托管与直接启动是两种场景**：用户可以复制、修改或直接执行原生插件文件。一呼只能对由宿主启动的会话施加沙箱和能力策略，不能声称能控制脱离宿主的普通 Linux 程序。若要进一步收紧脱离宿主后的能力，公开市场优先采用 WASM/WASI 或声明式插件。
3. **公开版默认不信任第三方插件**：对执行环境严格，对宿主能力 API 开放；扫描、审核和签名降低风险，但不能证明插件内部逻辑绝对正确。
4. **权限分两层**：公共 manifest 表达宿主能力（如 `clipboard.write`、`open_uri`、`selected_files.read`）；`fs-read`、`fs-write`、`network` 只作为受控原生插件的沙箱配置，不能解释成任意系统权限。`data_dir` 为自动提供的专属目录，剪贴板等能力由宿主托管。
5. **原生插件必须有强制隔离**：公开版缺少 bwrap 或等价 namespace/Landlock/seccomp 隔离时，拒绝安装或运行；只有显式开发者模式允许明示降级。
6. **能力代理优先**：插件不得获得通用 `exec`、任意 D-Bus 调用、任意路径写入或宿主会话总线；系统交互通过窄能力接口，由宿主检查 manifest、策略、参数和用户确认后执行，并记录审计事件。

## 一期：权限沙箱与分发基础

1. **权限声明 v1**：manifest 增加 `[permissions]`/能力声明结构，字段从 v0 实际能力面反推——
   公共层声明 `clipboard_write`、`open_uri`、`launch_app`、`selected_files_read`、`active_window_read`、受限 `network_fetch` 等宿主能力；
   原生沙箱层再表达 `network`、`fs-read` / `fs-write` 等最小挂载配置。权限名称、参数和路径白名单必须有严格校验，中心插件页同步展示明细。
2. **bwrap 沙箱强制化**：宿主托管的原生会话统一走 bwrap（`--unshare-all` + FS 白名单 + `--die-with-parent`），并清理敏感环境变量、额外 FD、宿主 D-Bus 和任意 Unix socket；白名单 = 插件目录（只读）+ 独立 `data_dir`（读写）+ 明确声明的路径 + 运行必需系统路径（只读）。权限未声明的访问在沙箱层失败。
3. **能力代理与审计**：增加受控 `capability_request` 消息和一次性会话凭证/专属 FD 或私有 socket；无有效宿主凭证的直接启动不能调用一呼能力代理。优先提供剪贴板写入、打开 URI、受限启动应用、选中文件读取、活动窗口摘要和受限网络请求；所有请求、拒绝、确认、超时、崩溃与资源超限可审计。
4. **zip 分发**：包格式 = `zip{ manifest.toml, entry, 资源 }`；安装时校验 manifest 全套规则、路径穿越、符号链接/特殊文件、zip 炸弹、文件数/体积/压缩比上限，并在临时目录验证后原子提交。市场包必须绑定源码仓库固定 commit、依赖锁文件、构建信息、SHA-256、签名、SBOM 和能力声明；普通第三方市场不接受只有二进制且无可核验源码的包。
5. **插件市场 v0**：GitHub PR 审核模式——市场仓库维护 registry 索引，CI 自动校验 manifest/结构、源码与构建物关联、依赖/secret/license/SBOM 和基础动态探针，人工审核权限合理性；中心页市场浏览、签名校验与一键安装。支持撤销、下架、回滚；呼出路径不碰网络（零 IO 底线不变），市场功能只存在于中心应用。

## 二期：UI 形态与触发扩展

6. **UI 插件形态 PoC + 决策**：受控 WebView（webkitgtk 按需进程、收起杀灭）vs 原生模板（插件声明式描述 UI，宿主 GTK 渲染）。先做 PoC 实测空载 PSS、冷启动、呼出延迟，对照宗旨红线再定；公开市场不得因 UI 方便而取消能力代理和沙箱。
7. **files/window 触发**：`query` 消息增加可选 `context` 字段（选中文件、活动窗口等上下文；加字段向后兼容，仍属 `api:1`，不动协议主版本）。上下文通过宿主能力和用户策略提供，不把整个文件系统或窗口服务暴露给插件。
8. **常驻 provider**：socket-activation + 空闲自退——常驻的收益（免 spawn）与零进程宗旨的调和形态，参照调研 §1.1 结论；常驻不改变能力代理、凭证和沙箱要求。

## 穿插小项（不占独立期，随手做）

- 应用列表热刷新（`gio::AppInfoMonitor`；呼出路径零 IO 不变，只更新后台缓存）；
- 拼音/首字母索引（nucleo 匹配列增加拼音列，数据来源实施时定）；
- 电台 DBus 接口（优先由宿主提供窄能力接口，不向插件开放任意 DBus）；
- 崩溃禁用落盘（M3「本运行期粒度」待议项：5 分钟窗口超限写 `plugins_state.json`，中心页可恢复）；
- 安装收据与运行审计（插件版本/hash、来源、启动方式、沙箱状态、能力请求与拒绝）。

## 发布分级

- **官方插件**：可以使用受控原生实现，但必须签名、可追溯、强制沙箱、最小能力和可撤销。
- **市场第三方插件**：公开入口优先采用 WASM/WASI 或声明式插件；受控原生 provider 作为有审核、有源码、有签名构建证明的例外。
- **本地开发插件**：显式开发者模式、独立目录/命令和明显风险提示；不进入正式市场标识，不得把无沙箱运行伪装成普通安装。

## 开放决策（2026-10-07 实施前冻结）

| 决策点 | 落定 | 理由 / 代价 |
|---|---|---|
| 能力代理首批能力 | `clipboard.write` / `open_uri` / `launch_app` / `notify` / `selected_files.read`；`network.fetch` 不做 | 沙箱 `--unshare-all` 默认无网络；受限网络代理列 M5。代价：需联网插件 v1 装不了，诚实性优先 |
| `fs-read`/`fs-write`/`network` | 不设字段 | 沙箱白名单固定「插件目录只读 + data_dir 读写」，不做任意路径配置 |
| 会话凭证形式 | 管道即凭证 | 宿主拉起会话独有 stdio，直接启动进程无通道可发；token 可复制、管道不可伪造。审计关联 (plugin, gen, ts) |
| 用户确认策略 | 安装时权限明示 = 授权时点，不做每请求弹窗 | 弹窗打断呼出体验且阻塞主循环；参数级校验兜底（scheme 白名单、长度上限），审计可查 |
| registry 信任根 | v0 = sha256 + 体积核对，每包绑定 | 市场仓库与信任根尚不存在，先签名是无根之木；ed25519 列 M5 正式市场前 |
| 常驻 provider 形态 | manifest `resident` + 收起不杀 + 空闲 300s 发 shutdown 自退（5s 宽限强杀） | systemd socket-activation 收益只对重型解释器明显、逐插件 unit 复杂，列 M5 |
| context 来源 | Nautilus 扩展 v2 显式动作注入（右键「加入一呼搜索」→ SelectFiles DBus），收起即失效 | 不做全局选区/剪贴板监听（隐私 + Wayland 无全局 API）；活动窗口读取 Wayland GNOME 无 API，不做 |
| UI PoC | 脚手架已建（tools/uic-poc），native 腿已实测；web 腿待装 libwebkitgtk-6.0-dev 后 `--features web` 补测 | 数字必须真测；web 腿超线直接取原生模板，不折衷 |

仍未冻结（M5 实施前定）：公开市场默认运行时（WASM/WASI / 声明式 / 受控原生范围）、bwrap 缺失机器的开发模式降级细节、registry 签名信任根与可复现构建、开发模式目录/命令/UI 标识。
