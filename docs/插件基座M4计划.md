# 插件基座 M4 计划（第二期）

> 依据：[插件基座调研](插件基座调研.md) §3/§5、[插件基座M3计划](插件基座M3计划.md)「遗留到 M4+」。状态：**规划中（2026-09-20）**。
> 宗旨：延续「性能高、资源占用率低」。本期主题 = **安全收口 + 生态分发 + UI 形态决策**：
> 权限从「声明 + 明示」走向强制沙箱兜底；插件从「本地目录手工装」走向「zip 一键装 + 市场审核」；
> 并用实测数据敲定 UI 插件的进程形态。

## 一期：权限沙箱与分发基础

1. **权限声明 v1**：manifest 增加 `[permissions]`，字段从 v0 实际能力面反推——
   `network`（插件自行联网）、`fs-read` / `fs-write`（目录白名单）；
   `data_dir` 为自带赠予、剪贴板由宿主托管（v0 激活语义），均不设字段。
   中心插件页同步展示权限明细（已有基础）。
2. **bwrap 沙箱强制化**：会话 spawn 统一走 bwrap（`--unshare-all` +
   FS 白名单 + `--die-with-parent`）；白名单 = 插件目录（只读）+ data_dir（读写）
   + 声明路径 + 运行必需系统路径（只读）。权限未声明的访问在沙箱层失败。
3. **zip 分发**：包格式 = `zip{ manifest.toml, entry, 资源 }`；安装时校验
   （manifest 全套规则、路径穿越拒绝、zip 炸弹/体积上限）；中心页「从 zip 安装」。
4. **插件市场 v0**：GitHub PR 审核模式——市场仓库维护 registry 索引，
   CI 自动校验 manifest/结构，人工审核合并；中心页市场浏览与一键安装。
   呼出路径不碰网络（零 IO 底线不变），市场功能只存在于中心应用。

## 二期：UI 形态与触发扩展

5. **UI 插件形态 PoC + 决策**：受控 WebView（webkitgtk 按需进程、收起杀灭）
   vs 原生模板（插件声明式描述 UI，宿主 GTK 渲染）。先做 PoC 实测空载 PSS、
   冷启动、呼出延迟，对照宗旨红线再定，杜绝拍脑袋（调研 §1 的进程成本数据为底）。
6. **files/window 触发**：`query` 消息增加 `context` 字段（选中文件、活动窗口
   等上下文；加字段向后兼容，仍属 `api:1`，不动协议主版本）。
7. **常驻 provider**：socket-activation + 空闲自退——常驻的收益（免 spawn）
   与零进程宗旨的调和形态，参照调研 §1.1 结论。

## 穿插小项（不占独立期，随手做）

- 应用列表热刷新（`gio::AppInfoMonitor`；呼出路径零 IO 不变，只更新后台缓存）；
- 拼音/首字母索引（nucleo 匹配列增加拼音列，数据来源实施时定）；
- 电台 DBus 接口；
- 崩溃禁用落盘（M3「本运行期粒度」待议项：5 分钟窗口超限写 `plugins_state.json`，中心页可恢复）。

## 验收门槛

| 指标 | 门槛 | 结论 |
|---|---|---|
| 面板待命 PSS | 与 M3 持平（~20 MB） | |
| 收起后插件进程 | 0 | |
| bwrap 开销 | 插件查询 P95 延迟增幅 < 5 ms | |
| 沙箱有效性 | 探针插件读未声明路径必须失败 | |
| zip 安装安全 | 路径穿越 / 炸弹样本全部被拒 | |
| 市场端到端 | 浏览 → 安装 → 呼出可用 | |
| UI 形态 | PoC 数据齐备并出决策记录 | |

## 开放决策（实施时定，先立此存照）

- bwrap 缺失的机器：拒装 vs 明示降级运行（倾向后者 + 中心页常驻警示）；
- WebView PoC 若内存/延迟超红线，直接取原生模板，不再折衷；
- 市场 CI 可自动化的校验深度（manifest 校验全自动化，人工只审权限合理性）。
