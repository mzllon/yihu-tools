# M7 · 插件中心全量管辖（全量插件化 + 全生命周期）——W4～W10 路线图

> 2026-10-15 立项。北极星：**插件中心成为一呼所有能力的唯一管辖面**——一切能力皆插件，
> 生命周期九环节（发现/安装/启停/更新/权限/进程/数据/卸载/开发）全部有 UI、有状态、有审计。
> 对标 uTools「一切皆插件」的插件中心形态。
>
> 守住《插件运行时架构》终版四原则：官方=Rust、第三方=WASM、能力即安全（manifest
> permissions = 白名单）、呼出路径零 IO。

## 宿主内核边界

激进路线下仍必须留在宿主的：面板本体、中心壳、应用启动器/拼音/历史、托盘、呼出定位闭环、
插件基础设施本身。uTools 同样有内核——这不违背「一切皆插件」的能力管辖承诺。

## 现状基线（2026-10-15 三路调研结论）

已有：双轨运行时（bwrap+stdio / wasmtime+`export_plugin!`）、21 能力声明制 + 逐请求校验 +
审计、市场 sha256 安装链 + 收据、数据管理、/proc 实扫运行状态、Rust SDK；W3 五插件 WASM
生产；5 个系统插件定义（autodark/syscmd/webdirect/calc/applinks，进程内、面板按 owner 过滤）。

关键缺口：
1. **生产 WASM 轨无能力面**：`wasm_plugin.rs` Linker 为空、无 activate/无 ui.show/无审计，
   query 失败被 `.ok()` 静默吞。
2. 系统插件无中心 UI：《功能清单》称「中心插件页统一启停 ✅ M4」与代码不符（2026-10-09
   插件中心重构疑似丢失，本计划一并修正）。
3. 无更新/版本比对；无 ed25519 信任根；审计 `read_recent` 无调用方；收据只写不读；
   WASM 插件不在 PluginStatus。

## 波次

### W4 · WASM 能力面补全（一切的地基，先行）

1. `wasm_plugin.rs` 接入能力桥：W2 spike 的 `cap.rs` 转正——Linker 注入能力函数、
   activate 链路、`ui.show` 转宿主 `ui.rs` 渲染、能力请求统一走 `caps.evaluate()` + 审计
   （与 stdio 轨同一套限额/校验）。
2. `docs/wit/yihu-plugin.wit` 扩至 21 能力；manifest permissions = import 白名单，
   **装载期校验**（未声明的 import = 拒载，fail-fast，延续「能力即安全」）。
3. query 失败计入失败滑窗（去掉静默 `.ok()`）；WASM 插件进 PluginStatus（loaded/实例内存）。

**验收**：W3 五插件回归全过；新写官方「深浅色切换」WASM 插件（settings.write + notify）
跑通 query→activate→能力→审计全链路；呼出性能实测不破红线（.cwasm 缓存 ~0.4ms/模块）。

### W5 · 插件中心生命周期全量 UI + 签名信任根

1. **系统插件分区**：已装页新增「系统插件」卡片组（开关 + 说明），启停走现有
   plugins_state.json；同步修正功能清单.md。
2. **更新生命周期**：刷新时比对 registry `version` 与已装 receipt → 「可升级」徽标 →
   一键升级（下载→sha256→staging 原子替换→收据更新）；收据读取展示（来源/版本/安装时间）。
3. **权限运行时面**：插件详情「最近能力请求」视图（首个 `audit::read_recent` 调用方）；
   权限撤销 = 面板侧拒绝列表（manifest 不动、审计 deny）。
4. **停用即时化**：开关 → D-Bus 通知面板终结该插件现有会话。
5. **ed25519 信任根**：registry 签名 + 包签名，公钥内嵌宿主；无签名包仅高级安装通道可入。
6. sys-theme 演示插件从默认安装清单移除并本机卸载（搜索去重）。
7. 移除插件时可选删除数据目录。
8. **新增 `settings.watch@schema` 感知能力**（2026-10-16 用户需求：主题变色插件要能
   感知）：插件声明订阅 schema（如 org.gnome.desktop.interface color-scheme），键变化
   时宿主主动推 `on_response`/`on_ui_event` 风格事件；宿主侧以轮询闭环取值（面板主题
   跟随同款教训：dconf watch 不可靠）。深浅色官方插件借此支持「跟随系统」模式。

**验收**：九环节 UI 覆盖核对表逐项过；升级路径真机演练（低版本→高版本→回滚）；
UI 样式按惯例先出多档预览供选。

### W6 · 第一批内置单元转正（低难度，全部走 WASM）

webdirect（纯词法 + open_uri）、calc（纯计算 + clipboard.write）、夜灯开关
（settings.read/write）、**深浅色切换行**（吸收 sys-theme 语义为官方插件）、应用跟随适配器
（fs.read/write@~/.config/** + ui.show 表单）。

每迁一个：`providers.rs` 摘内置实现 → SYSTEM_PLUGINS 除名 → 插件中心成卡。
applinks（打开中心）实施时定去留（宿主引导件候选）。

**验收**：迁移后停用即搜索零残留；呼出零 IO 复测。

### W7 · 系统命令包转正（新窄能力 sys.command）

新增 `sys.command` 声明制能力：**固定命令白名单**（lock/suspend/poweroff/reboot/empty-trash，
无参数、不给任意 exec），沙箱探针加对应自检项。syscmd 五项迁移（截图工具/文件管理器入口走
现成 open_uri/launch_app）。

**验收**：探针全过；词表外命令宿主拒绝 + 审计。

### W8 · 插件模型扩展（激进路线支柱，两新形态）

1. **schedule 形态**：manifest 增 `[schedule]`（日历/间隔 + persistent）；宿主提供
   **通用 runner**——单一共享 systemd user timer 每分钟拉起 runner，runner 按注册表调
   到期的 schedule 插件 `on_tick`；错过的 tick 用 last-run 时间戳补跑（替代 systemd
   Persistent）。AutoDark 的判定/切换逻辑即迁此形态。
2. **native 官方插件形态**：架构终版「官方=Rust 原生」落地为进程型官方插件（同包分发、
   manifest + 中心卡片 + 生命周期管理，own GTK 主循环）。**capability 后端可注册自插件**
   （宿主执行能力时经注册表解析后端）。

先 spike：schedule runner 最小实现 + native 进程插件被中心纳管。

**验收**：一个 schedule 演示插件被共享 timer 准点唤醒且挂起补跑正确；一个 native 演示
插件在中心可启停/显示状态。

### W9 · 三大件迁移落地

1. **AutoDark → schedule 插件**：判定逻辑（含深色时段模型）、sun.rs 计算进 WASM；
   宿主 = timer + runner + settings.write。`autodark-agent` 退役（由通用 runner 取代）。
   中心「主题切换」页过渡为插件配置面（声明式 config spec 或保留原生页，实施时按 UI 权衡量）。
2. **截图引擎 → native 官方插件**：独立进程 own GTK 覆盖层/贴图窗（mdworkbench 先例解决
   gtk 链接冲突）。**风险前置 spike**：portal Screenshot 授权按调用方计，非宿主进程可能弹
   授权——若 portal 拒绝则诚实降级为「引擎留 host capability + 插件持入口/参数」，结论落档。
3. **MD 工作台 → native 官方插件**：入口行进插件；md.render/md.view 后端经注册表解析到
   该插件二进制。

**验收**：中心插件页三张卡可见可管；AutoDark 定时切换真机 24h 曲线；截图/贴图全功能回归。

### W10 · 终态收口

全能力清点核对表公示（每个面板行/中心页/系统能力 → 归属插件或宿主内核）；功能清单/README/
AGENTS 过时段落修正（电台页、MPRIS、cover_disc 死代码清理）；里程碑复盘。
