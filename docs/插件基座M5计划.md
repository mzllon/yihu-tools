# 插件基座 M5 计划（开放 API 时代）

> 依据：[功能清单](功能清单.md) M5 行、[插件基座 M4 计划](插件基座M4计划.md)「仍未冻结」项、[uTools 对标与生态路线](uTools对标与生态路线.md)。
> 状态：**分批推进中**（本文档 2026-10-11 建立时，前三批已落地）。M5 不立单次大坝，按「能力面 → 数据面 → 生态面」分批交付，每批独立可验证。

## M5 全景（来自功能清单，滚动维护）

剪贴板历史、关键字直达、UI 插件层、市场签名信任根、受限网络代理、自定义快捷命令、超级面板文本触发调研、socket-activation、电台窄能力接口、插件数据管理。

## 已落地批次

### 第一批：开放 API v2（2026-10-10，commit 7074dcd）

能力面从「词表白名单」升级为「**能力@参数**声明制」（用户拍板：沙箱为底、API 做宽、申请制；uTools 的「释放沙箱」路线明确否决）：

- 带参能力：`network.fetch@host`（域名白名单）、`settings.write@schema`、`fs.write@glob`（`~` 展开、`*` 不跨层、`**` 跨层、归一化后匹配）；
- 插件进程仍在 bwrap 沙箱内（无网无 FS），系统访问全部经宿主代执行；
- manifest 声明 → 安装页徽章明示 → 逐请求参数校验 → audit.jsonl 留痕。

### 第二批：UI 插件层 v1（2026-10-10，commit c9af673）

协议加法扩展 `ui.show` / `ui.event` + 宿主原生模板表单渲染器（`panel/ui.rs`：text / hotkey 按键捕获 / app_select 下拉）；同 `ui_id` 重复 show 替换，UI 打开期间会话 pin（kill_all 豁免）。首用插件 hotkeys 重写为表单交互。

### 第三批：能力面扩容 + 插件数据管理（2026-10-11，本批）

**主题：沙箱能力足够强大（但不付出性能代价）+ 数据是用户可见、可带走的文件。**

1. **API v2 扩容两项**：
   - `fs.read@glob`：宿主代读 UTF-8 文本（≤4 MiB）。**符号链接逃逸防御**：授权期 canonicalize 后按真身复检声明 glob——声明目录内的链接指向声明外（如 `~/.notes/x → /etc/shadow`）直接拒绝；文件不存在也在授权期快反馈。
   - `clipboard.read`：宿主 gdk **异步**读（Wayland 下是到数据源的 IPC 往返，同步版会阻塞主循环——硬性规则 #1；完成回调推 cap_async 槽走统一泵）。≤1 MiB，隐私敏感能力、安装页明示。
   - 性能红线不变：两条都走「后台执行 + 结果槽 + 常驻泵回包」，不碰呼出热路径，不给插件进程开任何新口子（仍无网无 FS）。
2. **插件数据管理**（对标 Rubick「账户和设置 → 多端数据同步」页：按插件列数据、导出/导入）：
   - `yihu-core::datactl`：`data_stats`（文件数/字节）、`export_data_zip`（含 `yihu-data.json` 元数据条目）、`import_data_zip`（**校验强度与插件包安装相同**：穿越/符号链接/压缩比炸弹/条目数/解包总量；元数据 id 不匹配即拒绝——数据包装错插件直接报错）、`clear_data`；staging + rename 原子替换，失败不留半套数据。
   - 中心「插件」页每张已装卡片新增数据行：`N 个文件 · 大小` + 打开目录 / 导出 zip / 导入 zip / 清空（FileDialog 原生选框；导入/清空有 adw 确认弹窗；统计与操作全部后台线程 + 轮询回填）。
3. **审计失真修复**：`CapOutcome` 此前不带能力名，异步结果泵把所有能力都记成 `screenshot.take`（错误分支甚至记成插件 id）。补 `capability` 字段，泵按真实能力名记 `done`/`error`（授权时的 `grant` 仍在 handle_capability 记，两段语义分开）。
4. **示例插件 jsonkit**：JSON 工具——`clipboard.read` 读剪贴板 → 格式化/压缩/校验行，激活由宿主激活语义自动复制 payload（无需 clipboard.write）。协议内 clipboard.read 的第一个真插件。

## 设计决策记录（本批）

| 决策点 | 落定 | 理由 / 代价 |
|---|---|---|
| fs.read 的符号链接 | 授权期 canonicalize 复检真身 | 声明目录内链接可指声明外；在授权期拦（快反馈）而非执行期。代价：evaluate 一次 syscall（µs 级，不在热路径） |
| clipboard.read 形态 | 无参声明制 + gdk 异步读 | 同步读会阻塞主循环（BUG-001 同源风险）；声明制与整个 v2 一致，安装页明示 |
| 数据导出格式 | zip + 包内 `yihu-data.json` 元数据（插件 id、导出时间） | 导入时可拒收装错插件的数据包；空目录/纯文件均可导 |
| 数据管理入口 | 每张已装卡片一行（统计 + 4 个图标按钮），不新开页 | 对标截图形态且延续卡片网格语言；避免页数膨胀 |
| 移除插件是否删数据 | 不删 | 重装不丢数据；孤立数据目录由用户在数据行手动清（列 M6：移除时可选项） |
| 导入/清空确认 | adw MessageDialog 两键确认 | 破坏性操作不裸跑；GtkAlertDialogButton 属 GTK 4.14 超出本机特性集 |

# 第四批（2026-10-11）：UI 插件层 v2 + 工具箱系列四插件

> 用户从 uTools/ZTools 热门插件调研清单中挑选四项（开发者编码工具箱、SQL 格式化、
> 随机数生成器、随机密码生成器），要求全部带 UI。落地为「UI 层控件扩容 + 四个
> 参考实现」：类型化控件补齐后，纯计算类工具插件可以完全用声明式模板表达，
> 不需要新能力、不需要新协议消息。

## 内容

1. **UI 插件层 v2**（`panel/ui.rs`）：
   - 新控件：`textarea`（多行，GTK TextView）、`select`（通用下拉，choices 为
     `{label,value}` 或纯字符串）、`switch`（开关）、`number`（整数 SpinButton，
     min/max/step/value）。
   - `actions` 动作按钮：不关窗，点击回 `ui.event{event:"action:<key>",values:{当前全部字段}}`。
   - `output` 输出区：结果行（title/subtitle/copy/preview），行内「复制」由宿主
     直写剪贴板——与列表激活复制 payload 同一宿主语义，插件**无需 clipboard.write**。
   - 同 `ui_id` 重复 show = **原地重建**（生成→看结果→调参→再生成不闪窗不丢焦点）；
     fields 改 RefCell，旧事件闭包读到的永远是最新字段。
   - submit 行只在纯表单出现（带 actions+output 的工具窗不再渲染多余「保存」）；
     hotkeys 旧表单行为不变。
2. **sessions.rs**：`send_ui_event` 由「仅 submit 带 values」改为「values 非空即内联」，
   cancel 依旧不带（对旧插件兼容）。
3. **工具箱系列四插件**（全部纯本地计算、`permissions = []`、查询全量广播下只认
   自己的词头）：
   - `devcodec` 开发者编码工具箱：Base64/URL 编解码、MD5/SHA-1/SHA-256、进制互转、
     大小写、JWT 解码；快捷路径 `b64 hello`/`jwt <token>` 首词别名直开直算。
   - `sqlfmt` SQL 格式化：纯标准库词法器（字符串/注释整段保留、多词关键字合并、
     子查询括号内整体缩进、IN 值列表保持同行）+ 关键字大写 + 主子句换行 + AND/OR
     独行多缩一层；「压缩」去注释收空白。
   - `randgen` 随机数生成器：整数（secrets 密码学安全）/浮点/UUID v4/硬币/骰子；
     `rand 5-20` 带范围直开。
   - `passgen` v0.2 随机密码生成器（推翻 0.1 文本指令行交互）：长度/个数数字框、
     四类字符集开关、风格三选（随机字符·每类至少一位 Fisher–Yates / 数字 PIN /
     易读短语·音节词+数字尾缀）；`pass 20` 预填长度。

## 设计决策记录（第四批）

| 决策点 | 落定 | 理由 / 代价 |
|---|---|---|
| 动作按钮 vs submit 关窗 | 工具型用 actions 不关窗 + output 行内复制 | 「生成→看结果→调参→再生成」是工具的主循环，回面板列表体验断裂；submit 关窗模型保留给表单型（hotkeys） |
| 复制能力归属 | output 行内复制宿主直写剪贴板 | 与激活复制 payload 同语义，工具箱系列得以零权限声明；代价：复制不经插件审计（与列表激活一致，可接受） |
| 同 ui_id 重建 | 原地 set_child 替换，不关窗重开 | 关窗重开会闪窗、抢焦点；fields 用 RefCell 让既有闭包读新字段，事件配对语义不变 |
| SQL 格式化实现 | 纯标准库词法，不引 sqlparse | 沙箱 /usr 只读、无 pip 通道；词法级（字符串/注释保留 + 缩进 + 大写）已覆盖日常可读性诉求 |
| 随机源 | secrets（密码学安全）+ 每类字符集至少一位 | 密码/抽奖场景不可预测是底线；Fisher–Yates 洗牌保证「每类至少一位」不破坏均匀性 |
| 插件 query 匹配 | 全量广播下插件自认词头（hints/首词别名），不匹配静默 | 与既有协议一致（triggers 仅元数据），无宿主改动 |

## 踩坑记录（第四批）

- **cp -r 直拷注册表丢执行位**：开发迭代绕过 `install_from_dir`（它会给入口补
  0o755）用 `cp -r` 装插件，新文件落 644 → bwrap `execvp /plugin/xxx.py:
  Permission denied`，会话拉起后静默消失（调试日志才有 bwrap 报错）；passgen 因
  cp 覆盖旧文件保留原 755 模式而幸存，极具误导性。教训：**直拷注册表后必须
  `chmod 755` 入口**；仓库源文件已加 git 执行位双保险，zip/目录安装通道本就
  会补位。
