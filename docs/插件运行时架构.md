# 一呼插件运行时架构（终版）

> 2026-10-11 敲定。本文档是插件基座的**架构终版决策**——后续开发以此为准，
> 不再更改方向。灵感来源：Java SDK/JVM 模型——**插件面向 SDK 接口编程，
> 沙箱即虚拟机，平台渲染器可插拔**。
>
> 关联：[跨平台路线.md](跨平台路线.md)、[插件基座安全模型与发布策略.md](插件基座安全模型与发布策略.md)。

## 0. 一句话架构

> **W1 spike 实测（2026-10-11）**：wasmtime 嵌入可行，性能假设全部验证——
> 编译缓存后加载 **0.4ms**（加速 519×）、实例化+调用 **0.18ms**、热调用
> **1.7μs**。对比现状 bwrap+Python 的 35-70ms 冷启动，**WASM 方案快 10-100×**
> 且跨平台免费。

```
插件（Rust → .wasm 组件）
    │  只调 SDK 接口：show-ui(spec)、clipboard.read()、…
    │  不知道自己跑在 Linux 还是 Windows
    ▼
wasmtime（虚拟机，嵌入面板进程）
    │  WASM 函数调用 → 转发给宿主
    ▼
宿主（panel 进程）
    ▼
PlatformShell trait（每平台一个实现）
    ├── Ubuntu/Linux → GTK4 渲染 spec（最佳实现）
    ├── Windows → egui 或 WinUI（spike 后定）
    └── Web 视图 → wry/WebView2（MD 工作台等富 UI）
```

## 1. 三条架构决策（用户拍板，终版）

| 决策 | 内容 | 敲定时间 |
|---|---|---|
| **官方插件 = Rust 原生** | 编译为独立二进制（过渡期）/ WASM 组件（终态），不是 Python | 2026-10-11 |
| **第三方插件 = WASM** | 公开市场第三方上架前必须编译为 .wasm 组件 | 2026-10-11 |
| **性能第一顺位** | 所有架构决策以运行时性能为首要约束 | 2026-10-11 |

## 2. 分层模型（Java 类比）

| 层 | Java 对应 | 一呼对应 | 职责 |
|---|---|---|---|
| 插件代码 | `.java` 源码 | Rust 源码 → `wasm32-wasip2` 组件 | 业务逻辑，面向 SDK 编程 |
| SDK / JDK | JDK 标准库 | **WIT 接口**（show-ui、clipboard.read、network.fetch…） | 插件可见的全部 API，类型安全 |
| 虚拟机 / JVM | JVM | **wasmtime**（嵌入面板进程） | 加载 .wasm、执行、安全隔离、资源限制 |
| 平台渲染器 | Swing/AWT 平台绑定 | **PlatformShell trait 实现** | 把 UI spec 渲染为原生控件；每平台一个实现 |
| 平台服务 | JVM 系统调用绑定 | PlatformShell | 截图、热键、通知、音频、路径、状态 |

**关键原则**：插件永远不直接接触 GTK/egui/WebView——它只调 SDK 接口，平台渲染差异由宿主的 PlatformShell 吸收。

## 3. UI 三层出口

| 层 | 适用 | 插件调用 | 宿主渲染 | 已有实现 |
|---|---|---|---|---|
| 结果行 | 搜索/转换/密码列表 | `show-results(items)` | 面板列表，回车复制/激活 | ✅ |
| 模板表单 | 结构化交互（表单+输出区） | `show-ui(spec)` | 原生 GTK4 控件（textarea/select/switch/number + 行内动作） | ✅ ui.show v2.1 |
| Web 视图 | 富交互（编辑器/播放器/图表） | `open-webview(html)` | WebKitGTK/WebView2 + 宿主桥（postMessage） | ✅ MD 工作台 |

**UI 永远由宿主渲染，WASM 插件不碰任何 UI 库**——沙箱里没有 GTK/WebView，这是安全模型的底线。

### 模板渲染器可插拔

| 平台 | 渲染器 | 状态 | 理由 |
|---|---|---|---|
| **Ubuntu/Linux** | **GTK4** | ✅ 已有 | 原生观感、Wayland 集成、GPU 加速、待命零功耗、无障碍——压倒性最佳 |
| **Windows** | egui 或 WinUI | ⏳ spike 后定 | egui：纯 Rust 零 C 依赖、cargo 直出；WinUI：原生观感 |
| **Web 视图** | wry（WebKitGTK / WebView2） | ⏳ spike 后定 | TOAST UI 等 web 编辑层零改动 |

### egui 定位（Windows 备选，非 Linux 替换）

egui 性能数据：单帧 <0.5ms（简单表单）、内存 ~5-10MB、启动 1-5ms、纯 Rust 零 C 依赖。
代价：immediate-mode 60fps 持续重绘（空闲 CPU ~1-5%，需 reactive 模式缓解）、非原生观感。
**Linux 上不换**——GTK4 的事件驱动零功耗 + 原生观感 + Wayland 集成是压倒性优势。
**Windows 上是 GTK4-Windows 打包痛苦时的 B 计划**。

## 4. WASM 沙箱详解

### 为什么 WASM 而非 bwrap

| 维度 | bwrap + OS 进程（现状） | wasmtime（目标） |
|---|---|---|
| 冷启动/插件 | 35-70ms（fork+namespace+解释器） | 1-5ms（模块实例化） |
| 内存/插件 | ~17MB（bwrap+Python） | ~1-5MB（wasm 线性内存） |
| 能力调用 | JSON→pipe→反序列化 ~0.1-1ms | **直接函数调用 ~ns** |
| 安全模型 | bwrap 隔离 OS 资源 | **能力即安全**：未导入的 WIT 函数物理不可达 |
| 跨平台 | Linux 专属 | Windows/Linux/macOS 同一运行时 |
| 脱离宿主后 | 仍是普通用户程序 | 只是计算包，无任何系统能力 |

### 能力面 = WIT 接口

现有 `能力@参数` 声明制**原样映射**为 WIT 导入函数：

```
// WIT 接口草案（节选）
package yihu:plugin;

interface host {
    show-results: func(query-id: u64, items: list<result-item>);
    show-ui: func(ui-id: u64, spec: string);
    clipboard-read: func() -> result<string, string>;
    clipboard-write: func(text: string) -> result<_, string>;
    network-fetch: func(url: string) -> result<string, string>;
    audio-play: func(url: string) -> result<_, string>;
    notify: func(summary: string, body: string);
    open-webview: func(html: string) -> result<_, string>;
    // …每增加一种能力 = 增加一个 WIT 函数 + 宿主实现 + manifest 校验
}

world plugin {
    import host;
    export query: func(text: string) -> list<result-item>;
    export handle-event: func(event: string, data: string) -> result<_, string>;
}
```

- manifest `permissions` = WIT world 的 import 白名单（构建期检查，未声明的函数不可调用）；
- 宿主侧授权/审计管线不变（每次 WIT 调用过同一套校验）；
- `capability_request` JSON 消息被 WIT 函数调用取代（**零序列化开销**）。

### 双轨过渡

| 插件类型 | 运行时 | 状态 |
|---|---|---|
| 已有 Python 插件（radio/hotkeys/screenshot/mdkit/qrtool/stickynotes/todo 等） | bwrap + stdio JSON（现有管线） | 继续运行，逐批迁移 |
| 首批 Rust 插件（cronkit/csvkit/randgen/passgen/sqlfmt） | 编译为 .wasm 组件，面板内嵌 wasmtime 执行 | W1 spike 后 |
| 第三方市场插件 | .wasm 组件（强制） | 公开市场启动时 |

### wasmtime 选型

wasmtime 是 Bytecode Alliance 项目（Fastly/Shopify/Databrick 生产级使用），
WASI 0.2 组件模型已稳定。嵌入面板增加 ~20-40MB 二进制体积（一次性成本），
运行时按插件实例化（每个实例 1-5MB 内存）。

## 5. 平台渲染器（PlatformShell trait）

```rust
trait PlatformShell {
    // UI
    fn render_template(&self, ui_id: u64, spec: &Value);       // GTK4 (Linux) / egui (Windows)
    fn render_results(&self, items: &[Value]);
    fn open_webview(&self, html: &str) -> WebViewHandle;        // WebKitGTK / WebView2 (wry)
    // 系统服务
    fn screenshot_freeze(&self) -> Result<Pixbuf>;              // portal / DXGI
    fn global_hotkey(&self, key: &str, cb: Callback);
    fn notify(&self, summary: &str, body: &str);
    fn set_volume(&self, pct: u32);
    // 路径与状态
    fn data_dir(&self) -> PathBuf;
    fn pictures_dir(&self) -> PathBuf;
}
```

- **Ubuntu/Linux 实现**：GTK4 渲染器 + portal 截图 + gsettings 热键 + pactl 音量（现有代码收拢）
- **Windows 实现**：egui 或 WinUI 渲染器 + DXGI 截图 + RegisterHotKey + WASAPI（Stage 2 spike 后排期）
- **包管理提示**：`yihu_core::distro::install_hint()`（已有，apt/dnf/pacman/zypper 自适应）

## 8. 明确不做

- 在 WASM 里跑 Python（CPython→WASM 可行但内存 40MB+ / 启动 200ms+）
- KDE/deepin 面板定位与全局热键对等实现（Wayland 协议缺失）
- GTK 之外的 UI 栈重写面板壳（Qt/Electron）
- Windows 版市场签名链（等 Linux 侧落地后复用设计）
- 元素级自动吸附（Windows UIAutomation 专属，Linux 无对等 API）
